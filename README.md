# mruby/c for Zephyr

[![Ask DeepWiki](https://deepwiki.com/badge.svg)](https://deepwiki.com/OpenBlink/mrubyc-zephyr)

Run Ruby bytecode in a Zephyr application using [mruby/c](https://github.com/mrubyc/mrubyc).
The module builds mruby/c with a Zephyr HAL for scheduler timing and console output.
Your application provides the memory pool and starts the Ruby tasks.

| Module release | mruby/c release | Host compiler | Bytecode |
| --- | --- | --- | --- |
| `v4.0.0` | `release4.0.0` | mruby `4.0.0` (`mrbc`) | `RITE0400` |
| `v3.4.1` | `release3.4.1` | mruby `3.4.0` (`mrbc`) | `RITE0300` |

The samples target Zephyr 3.7.2 (LTS) on `native_sim/native` and `qemu_cortex_m3`.
Use Zephyr SDK 0.16.9 for the Cortex-M3 build.
The module requires a 32-bit little-endian, single-core Zephyr configuration
with multithreading and a system clock.

## Run a sample

Install the [Zephyr 3.7 host tools and west](https://docs.zephyrproject.org/3.7.0/develop/getting_started/index.html).
For `native_sim/native` on a 64-bit Linux host, install the 32-bit C
development libraries and a compiler that can build 32-bit binaries.

~~~sh
west init -m https://github.com/OpenBlink/mrubyc-zephyr --mr v4.0.0 mrubyc-workspace
cd mrubyc-workspace
west update
python -m pip install -r zephyr/scripts/requirements.txt
ZEPHYR_TOOLCHAIN_VARIANT=host west build -b native_sim/native \
  modules/lib/mrubyc-zephyr/samples/hello
build/zephyr/zephyr.exe -stop_at=1
~~~

The sample prints `Hello from mruby/c on Zephyr!`.
See [`samples/vm_tasks`](samples/vm_tasks) for two Ruby tasks that share a scheduler.
Both samples include generated bytecode headers, so building them requires the
Zephyr toolchain alone.

## Add the module to an application

Add this project entry under `manifest.projects` in your west manifest.

~~~yaml
- name: mrubyc-zephyr
  url: https://github.com/OpenBlink/mrubyc-zephyr
  revision: v4.0.0
  path: modules/lib/mrubyc-zephyr
~~~

Run `west update mrubyc-zephyr`. For a checkout outside the manifest, pass
`-DEXTRA_ZEPHYR_MODULES=/absolute/path/to/mrubyc-zephyr` after `--` in your
`west build` command. Enable the module in your application's `prj.conf`.

~~~ini
CONFIG_MRUBYC=y
CONFIG_PRINTK=y
CONFIG_SYS_CLOCK_TICKS_PER_SEC=1000
~~~

`CONFIG_PRINTK` enables Ruby console output. Set the system clock rate so one
millisecond is an integer number of Zephyr ticks. With a coarser clock, Zephyr
rounds up each mruby/c timer period, so Ruby sleep and scheduling take longer.

## Run your own Ruby code

Build the host compiler with `rake` from the [mruby 4.0.0
source](https://github.com/mruby/mruby/tree/4.0.0). The resulting executable is
`bin/mrbc`. Confirm the version with `mrbc --version`, then compile your Ruby
source to a C header.

~~~ruby
puts "Hello from mruby/c on Zephyr!"
~~~

~~~sh
mrbc -Bapp_mrb --remove-lv -o app_mrb.h app.rb
~~~

Include the generated header in one C source file and start the VM from a
Zephyr thread.

~~~c
#include <stdint.h>
#include <mrubyc.h>

#include "app_mrb.h"

static _Alignas(8) uint8_t pool[40 * 1024];

int main(void)
{
    mrbc_init(pool, sizeof(pool));
    if (mrbc_create_task(app_mrb, NULL) == NULL) {
        return 1;
    }

    return mrbc_run() == 0 ? 0 : 1;
}
~~~

`mrbc_init()` starts the HAL timer. Keep the pool and bytecode alive for the
lifetime of the runtime, and access the VM from one Zephyr thread. Ruby tasks
share that thread and are scheduled by mruby/c. The scheduler returns when
there are no runnable, waiting, or suspended tasks. Size the pool and the
Zephyr thread stack for your application. Use bytecode built from sources you
trust and recompile those sources when changing bytecode versions.

For build-time generation, include the helper after `find_package(Zephyr)`.
If needed, pass `-DMRUBYC_MRBC=/absolute/path/to/mrbc` to CMake.

~~~cmake
include("${ZEPHYR_MRUBYC_MODULE_DIR}/cmake/mrubyc.cmake")
mrubyc_embed_script(app app_mrb app.rb)
~~~

The helper accepts Ruby source and generates `app_mrb.h` in the build directory.
Use a distinct C identifier for each bytecode array linked into your application.

## Upgrade from v3.4.1

1. Change the module's west manifest revision to `v4.0.0` and run
   `west update mrubyc-zephyr`.
2. Select mrbc 4.0.0 and regenerate all embedded bytecode from Ruby source,
   including headers checked into your application. mruby/c 4.0.0 rejects
   `RITE0300` bytecode.
3. Rebuild the firmware from a clean build directory. If your C code calls
   `mrbc_find_method()`, update it for the new `mrbc_class *` return type.

To return to v3.4.1, pin that revision and regenerate the application
bytecode with mrbc 3.4.0 before rebuilding.

## Configuration

| Kconfig option | Default | Purpose |
| --- | --- | --- |
| `CONFIG_MRUBYC` | `n` | Build the module. |
| `CONFIG_MRUBYC_MAX_VM_COUNT` | `5` | Maximum number of VM instances. |
| `CONFIG_MRUBYC_MAX_REGS_SIZE` | `110` | Default register capacity per VM. |
| `CONFIG_MRUBYC_MAX_SYMBOLS_COUNT` | `255` | Dynamic symbol table capacity. |
| `CONFIG_MRUBYC_FLOAT_{SINGLE,DOUBLE}` | `DOUBLE` | Float representation. |
| `CONFIG_MRUBYC_USE_MATH` | `n` | Enable the Math module with Float and a C library that provides its math functions. |
| `CONFIG_MRUBYC_USE_STRING_UTF8` | `n` | Use UTF-8 character indexing in supported String methods. |
| `CONFIG_MRUBYC_USE_UNICODE_CASE` | `n` | Add Unicode BMP case conversion when UTF-8 is enabled. |
| `CONFIG_MRUBYC_INT64` | `n` | Use 64-bit Ruby integers. |
| `CONFIG_MRUBYC_SUPPORT_OP_EXT` | `y` | Enable extended bytecode operands (`MRBC_SUPPORT_OP_EXT=1`). |

Extended operands are enabled by default. The other runtime options use
mruby/c defaults. The bundled release requires Float and String support.
The HAL uses a 1 ms scheduler tick and 10 ticks per time
slice. Use the Kconfig options to keep the application and runtime headers
in sync. Link additional Zephyr libraries that include `mrubyc.h` with
`zephyr_library_link_libraries(MRUBYC_API)`.

## Tests and contributions

Put mrbc 4.0.0 on your `PATH` and run Twister from the module's west workspace.
For Cortex-M3, install
[Zephyr SDK 0.16.9](https://github.com/zephyrproject-rtos/sdk-ng/releases/tag/v0.16.9)
with the Arm toolchain and QEMU.

~~~sh
ZEPHYR_TOOLCHAIN_VARIANT=host west twister -p native_sim \
  -T modules/lib/mrubyc-zephyr/samples -T modules/lib/mrubyc-zephyr/tests
ZEPHYR_TOOLCHAIN_VARIANT=zephyr west twister -p qemu_cortex_m3 \
  -T modules/lib/mrubyc-zephyr/samples -T modules/lib/mrubyc-zephyr/tests
~~~

Use English for issues, pull requests, review comments, and code comments.
For a bug report, include the Zephyr revision, board, module tag, and
configuration. Include the `mrbc --version` output when reporting a
bytecode issue.

Release tags run the test suite in GitHub Actions. A maintainer approves the
publish job in the `production` environment before the GitHub Release is created.
Configure `production` with required reviewers and a `v*` deployment tag policy
before pushing a release tag.
